# 0007. План і список покупок як окремі записи

Статус: прийнято

## Контекст

План тижня редагують кілька клієнтів одночасно, а записи в базу працюють за принципом «останній записав — той і правий». Якби тиждень був одним документом, дві одночасні зміни (одна людина додає вечерю, інша — обід) призвели б до втрати однієї з них.

## Рішення

- Кожна страва плану — окремий документ `planEntries` з полем `weekStart`.
- Ручні позиції списку покупок — окремі документи `shoppingItems`.
- Відмітка «куплено» для згенерованого рядка — окремий документ `shoppingChecks` з детермінованим id `<weekStart>~<productId>`; зняття відмітки видаляє документ.
- Сам список покупок і покриття харчування не зберігаються: вони обчислюються з плану під час рендеру.

## Наслідки

- Одночасні зміни різних страв чи позицій не конфліктують; конфлікт можливий лише при редагуванні однієї й тієї самої страви.
- Документи накопичуються з часом (орієнтовно до тисячі на рік при ліміті 25 000); за потреби старі тижні можна видаляти.
