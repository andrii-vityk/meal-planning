# 0005. Порти, адаптери й підключення до UI

Статус: прийнято

## Рішення

- **Порт сховища** (`application/ports/repository.ts`) має форму `subscribe` + `getSnapshot`, тобто саме ту, яку очікує `useSyncExternalStore` у React. UI підписується на будь-яку реалізацію без проміжних шарів (`ui/hooks/useCollection.ts`).
- **Знімок незмінний:** кожна зміна створює новий об'єкт, тож React визначає оновлення порівнянням посилань.
- **Порт AI** (`application/ports/ai.ts`) описує чотири задачі застосунку, а не «викликати модель». Помилки — `AiError` з кодами, які UI показує користувачу.
- **Дві реалізації:** платформа (база й Claude хоста) і in-memory (тести й локальна розробка, з вигаданими прикладами).
- **Точка композиції** (`src/main.tsx`) обирає реалізацію: якщо `window.claude` немає, працює in-memory.
- **Залежності в UI** передаються через React context (`ui/dependencies.tsx`); `AppRoot` чекає на них через `use(promise)` і `<Suspense>`.
- **Документи бази** читаються через ручні валідатори без сторонніх бібліотек (`infrastructure/serialization`); контракт описано в `docs/data-model.md`.

## Наслідки

- Нова залежність від зовнішнього світу = новий порт + дві реалізації.
- Тести UI використовують in-memory адаптери через `src/test/renderWithDependencies.tsx`, який, як і точка композиції, стоїть поза шарами.
