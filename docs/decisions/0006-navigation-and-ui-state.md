# 0006. Навігація й стан інтерфейсу

Статус: прийнято; пункти про розділи й екрани замінено [ADR 0008](0008-addressable-screens.md)

## Рішення

- **Розділи** адресуються хешем URL (`#recipes`). Хост артефакту передає лише простий `#name`, тож маршрути — плоский список імен без шляхів і параметрів. Поточний розділ читається через `useSyncExternalStore` з подією `hashchange`, як і дані з репозиторіїв.
- **Екрани всередині розділу** (список, перегляд, редагування, імпорт) — локальний стан компонента розділу у вигляді discriminated union, а не маршрути. Неможливі комбінації («редагування й імпорт одночасно») неможливо навіть записати.
- **Похідне обчислюється під час рендеру**, а не зберігається в стані: відфільтрований список, масштабовані інгредієнти.
- **Форми** тримають рядки (саме їх містять поля вводу) і перетворюються на доменні дані чистими функціями (`recipeFormState.ts`), які тестуються окремо від React.
- **Асинхронні дії** (збереження, AI) — через `useTransition`: прапорець `isPending` без ручного `useState(loading)`. AI-запити скасовуються через `AbortController`.
- **Стилі:** спільні класи контролів (`.button`, `.input`, `.field`) — у `global.css`, розкладка кожного компонента — у його CSS-модулі.
- **Тести** можуть використовувати in-memory адаптери напряму: правила шарів у лінтері діють лише для робочого коду.
