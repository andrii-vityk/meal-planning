# Вимоги

Вебзастосунок для збереження рецептів і планування харчування. Відповідає на два питання: «що приготувати зараз з наявних продуктів» і «що їмо цього тижня та що купити».

Мова інтерфейсу й даних — українська.

## Сценарії

1. **Зберегти рецепт.** Фото + довільний текст або вставлений текст рецепта. AI перетворює це на структурований рецепт, користувач підтверджує.
2. **Підбір страв.** Користувач текстом вводить наявні продукти. Базові запаси додаються автоматично. Результат — рецепти й фреймворки, які можна приготувати, з бракуючими інгредієнтами та можливими замінами.
3. **План на тиждень.** Усі прийоми їжі (сніданок, обід, вечеря, перекус). Одна страва може покривати кілька слотів (залишки). Для кожного дня видно, чи є в ньому джерело білка, клітковини, корисних жирів.
4. **Список покупок.** Генерується з плану, мінус базові запаси, групування за категоріями.
5. **Зовнішні записи.** Рецепти, продукти й фреймворки можуть записуватися в базу поза інтерфейсом (через Claude). Застосунок коректно показує такі зміни.

## Функціональні вимоги

| ID | Вимога | Деталі |
| --- | --- | --- |
| FR-01 | Рецепт | Назва, інгредієнти (кількість, одиниця, продукт), кроки, час, порції, мітки, прапорець «підходить дітям», посилання на джерело (обов'язкове для рецептів із сайтів). |
| FR-02 | Масштабування порцій | Перерахунок кількостей інгредієнтів. |
| FR-03 | Фото страви | Власне фото; зменшення до ~1600 px по довшій стороні, автообрізання під співвідношення картки. Без фото — нейтральна заглушка за типом страви. |
| FR-04 | Довідник продуктів | Один запис на продукт, синоніми, категорія, позначки поживності (джерело білка / клітковини / корисних жирів). Позначки ставить AI при додаванні продукту; користувач лише виправляє. |
| FR-05 | Базові запаси | Прапорець на продукті, без кількостей і обліку залишків. |
| FR-06 | Фреймворки | Шаблон зі слотами (основа, білок, овочі, соус…) і варіантами для кожного слота; варіант може мати прапорець «підходить дітям». |
| FR-07 | Ввід наявних продуктів | Вільний текст → зіставлення з довідником; нерозпізнане — пропозиція додати продукт. |
| FR-08 | Підбір страв | З наявного + базових запасів; бракуючі інгредієнти, заміни, фільтр «підходить дітям». |
| FR-09 | План на тиждень | Запис = страва + порції + один чи кілька слотів (день, прийом їжі). Конкурентне редагування з кількох клієнтів. |
| FR-10 | Покриття харчування | Якісне, по днях; без грамів і калорій. |
| FR-11 | Список покупок | З плану, мінус базові запаси; страва із залишками враховується один раз; групування за категоріями; ручні позиції. |
| FR-12 | Експорт / імпорт | Уся база в JSON-файл і назад. |
| FR-13 | Зовнішні записи | Стабільна, описана схема даних; UI реагує на зміни, внесені поза ним. |

### Бажано

| ID | Вимога | Деталі |
| --- | --- | --- |
| NTH-01 | Відмітка «куплено» в реальному часі | Синхронізація між клієнтами. |
| NTH-02 | Ручний кроп фото | Якщо автообрізання недостатньо. |
| NTH-03 | Збережені заміни | Підтверджені користувачем заміни продуктів. |

## AI-функції

| Функція | Вхід | Вихід |
| --- | --- | --- |
| Розбір рецепта | фото + текст або вставлений текст | рецепт з інгредієнтами, зіставленими з довідником |
| Зіставлення продуктів | вільний текст | продукти з довідника + нерозпізнане |
| Підбір і заміни | наявне + запаси + рецепти/фреймворки | ранжований список із бракуючим і замінами |

Імпорт за посиланням сторінка виконати не може (браузер блокує запити до сторонніх сайтів), тож він відбувається поза застосунком, через зовнішні записи.

Затримка AI-викликів ~1–2 с, перший виклик до ~10 с: кожен AI-виклик має видимий стан завантаження й можливість скасування.

## Поза обсягом

- Ціни, чеки, бюджет.
- Підрахунок калорій і грамів нутрієнтів.
- Облік залишків продуктів.
- Оцінки страв.
- Ідентифікація користувачів і авторство змін: база не зберігає жодних персональних даних.
- Чужі фото з сайтів рецептів — лише посилання на джерело.
