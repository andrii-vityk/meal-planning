# Вимоги

Вебзастосунок для збереження рецептів і планування харчування. Відповідає на два питання: «що приготувати зараз з наявних продуктів» і «що їмо цього тижня та що купити».

Мова інтерфейсу й даних — українська.

## Сценарії

1. **Зберегти рецепт.** Фото + довільний текст або вставлений текст рецепта. AI перетворює це на структурований рецепт, користувач підтверджує.
2. **Підбір страв.** Користувач текстом вводить наявні продукти. Базові запаси додаються автоматично. Результат — рецепти й фреймворки, які можна приготувати, з бракуючими інгредієнтами та можливими замінами.
3. **План на тиждень.** Усі прийоми їжі (сніданок, обід, вечеря, перекус). Одна страва може покривати кілька слотів (залишки). Для кожного дня видно, чи є в ньому джерело білка, клітковини, корисних жирів.
4. **Список покупок.** Генерується з плану, мінус базові запаси, групування за категоріями.
5. **Зовнішні записи.** Рецепти, продукти й фреймворки можуть записуватися в базу поза інтерфейсом (через Claude). Застосунок коректно показує такі зміни.

## Функціональні вимоги

| ID | Вимога | Деталі |
| --- | --- | --- |
| FR-01 | Рецепт | Назва, інгредієнти (кількість, одиниця, продукт), кроки, час, порції, мітки, прапорець «підходить дітям», посилання на джерело (обов'язкове для рецептів із сайтів). |
| FR-02 | Масштабування порцій | Перерахунок кількостей інгредієнтів. |
| FR-03 | Фото страви | Власне фото; зменшення до ~1600 px по довшій стороні, автообрізання під співвідношення картки. Без фото — нейтральна заглушка за типом страви. |
| FR-04 | Довідник продуктів | Один запис на продукт, синоніми, категорія, позначки поживності (джерело білка / клітковини / корисних жирів). Позначки ставить AI при додаванні продукту; користувач лише виправляє. |
| FR-05 | Базові запаси | Прапорець на продукті, без кількостей і обліку залишків. |
| FR-06 | Фреймворки | Шаблон зі слотами (основа, білок, овочі, соус…) і варіантами для кожного слота; варіант може мати прапорець «підходить дітям». |
| FR-07 | Ввід наявних продуктів | Вільний текст → зіставлення з довідником; нерозпізнане — пропозиція додати продукт. |
| FR-08 | Підбір страв | З наявного + базових запасів; бракуючі інгредієнти, заміни, фільтр «підходить дітям». |
| FR-09 | План на тиждень | Запис = страва + порції + один чи кілька слотів (день, прийом їжі). Конкурентне редагування з кількох клієнтів. |
| FR-10 | Покриття харчування | Якісне, по днях; без грамів і калорій. |
| FR-11 | Список покупок | З плану, мінус базові запаси; страва із залишками враховується один раз; групування за категоріями; ручні позиції. |
| FR-12 | Експорт / імпорт | Уся база в JSON-файл і назад. |
| FR-13 | Зовнішні записи | Стабільна, описана схема даних; UI реагує на зміни, внесені поза ним. |

## AI-функції

| Функція | Вхід | Вихід |
| --- | --- | --- |
| Розбір рецепта | фото + текст або вставлений текст | рецепт з інгредієнтами, зіставленими з довідником |
| Зіставлення продуктів | вільний текст | продукти з довідника + нерозпізнане |
| Підбір і заміни | наявне + запаси + рецепти/фреймворки | ранжований список із бракуючим і замінами |
| Чернетка тижня (FR-14) | тиждень з наявними записами + рецепти/фреймворки + історія 2 тижнів + побажання | записи плану для порожніх слотів |

Імпорт за посиланням сторінка виконати не може (браузер блокує запити до сторонніх сайтів), тож він відбувається поза застосунком, через зовнішні записи.

Затримка AI-викликів ~1–2 с, перший виклик до ~10 с: кожен AI-виклик має видимий стан завантаження й можливість скасування.

## Переробка зручності (цикл 2)

Мета — менше дій на типові задачі. Усі задачі (план, покупки, підбір страв, зрідка рецепти) виконуються в інтерфейсі; зовнішні записи (FR-13) лишаються допоміжним шляхом, а не основним.

### Термінологія інтерфейсу

У рядках інтерфейсу фреймворк називається **«конструктор»**, слот — **«складова»**, варіант — **«варіант»**. Ідентифікатори в коді й схема даних не змінюються (`framework`, `slots`, `options`).

### Вимоги

| ID | Вимога | Деталі |
| --- | --- | --- |
| UX-01 | Навігація «Назад» | Системна кнопка (жест) «Назад» повертає на попередній екран: зі сторінки страви — до списку, з редактора — до перегляду, між розділами — до попереднього розділу. Кожен екран має власну адресу, яку можна відкрити напряму. Переглядає ADR 0006 (плоский `#name`); можливості хоста перевіряються спайком на початку етапу 1. |
| UX-02 | Збереження стану розділів | Перемикання розділів не скидає введене й відкрите (розпізнані продукти, відкрита страва, обраний тиждень). |
| UX-03 | Стартовий розділ | «План». |
| UX-04 | Навігація на вузьких екранах | Панель розділів унизу екрана. |
| UX-05 | Розділ «Страви» | Рецепти й конструктори в одному списку; фільтр за типом (усі / рецепти / конструктори); пошук по всіх стравах; спільна кнопка «Додати» (рецепт, конструктор, імпорт). Замінює окремий розділ рецептів і вкладку фреймворків. |
| UX-06 | Перегляд конструктора | Окремий екран перегляду (складові з варіантами, опис, нотатки) з діями «Редагувати» і «В план»; редактор відкривається лише з нього. |
| UX-07 | «В план» з будь-якої страви | Одна спільна панель: вибір днів і прийомів їжі тапами (кілька одразу), порції з рецепта за замовчуванням, вибір варіантів для конструктора. Доступна з перегляду рецепта, перегляду конструктора й результатів підбору. |
| UX-08 | Редагування комірки плану | Та сама панель, відкрита з комірки, з наперед обраними днем і прийомом їжі; один пошук по всіх стравах плюс введення довільного тексту. На вузьких екранах — панель знизу (bottom sheet). |
| UX-09 | Результат збереження | Видиме підтвердження або повідомлення про помилку для кожного запису в базу. |
| UX-10 | «Є вдома» | У списку покупок позначка «є вдома» для тижня, окремо від «куплено». |
| UX-11 | Резервна копія | Експорт і імпорт — у розділі налаштувань, поза щоденними екранами. |

### FR-14. AI-чернетка плану на тиждень

| Аспект | Правило |
| --- | --- |
| Що заповнюється | Лише порожні слоти обраного тижня. Наявні записи не змінюються і передаються як обмеження. |
| Виключення | Перед генерацією можна вимкнути окремі дні або прийоми їжі. |
| Перекуси | Довільним текстом, без рецептів. |
| Джерело страв | Збережені рецепти й конструктори; для конструктора чернетка обирає варіанти складових. До 2 нових страв на тиждень текстом, з позначкою «пропозиція». |
| Повтори | Рецепт не пропонується, якщо він був у плані протягом 2 попередніх тижнів. Конструктор може повторюватися з іншими основними варіантами. |
| Залишки | Страва може займати слот того ж дня й наступного дня (один запис, кілька слотів). |
| Спільні складові | Варіант складової конструктора (напр. гарнір) можна приготувати один раз і використати в іншій страві-конструкторі наступного дня або через день. Це дозволено, але не обов'язково. Як така складова рахується в списку покупок — окреме рішення (ADR). |
| Харчування | Критерій: кожен день покриває білок, клітковину й корисні жири (FR-10). |
| Не враховується | Прапорець `kidFriendly` і час приготування. |
| Побажання | Необов'язковий вільний текст до запиту. |
| Підтвердження | Чернетка показується в плані візуально окремо й не записується в базу, доки її не прийнято. Дії: прийняти все, замінити окрему страву, згенерувати заново. |
| AI-виклики | Один запит на тиждень і один на кожну заміну; стани завантаження й скасування — як для інших AI-функцій. |
| Тестові дані | Згенерована вигадана історія кількох тижнів — у фікстурах тестів і демонстраційних in-memory даних. На час розробки база артефакту теж містить згенеровані дані; перед реальним використанням її очищують. |

### Етапи

1. Навігація і стан (UX-01…UX-04).
2. «Страви» й перегляд конструктора (UX-05, UX-06, UX-11).
3. Панель «В план» і редагування плану (UX-07…UX-09).
4. AI-чернетка тижня (FR-14).
5. «Є вдома» в списку покупок (UX-10).

## Поза обсягом

- Ціни, чеки, бюджет.
- Підрахунок калорій і грамів нутрієнтів.
- Облік залишків продуктів.
- Оцінки страв.
- Ідентифікація користувачів і авторство змін: база не зберігає жодних персональних даних.
- Чужі фото з сайтів рецептів — лише посилання на джерело.
